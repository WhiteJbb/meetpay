## Change and rationale

`GroupCard` previously called `Date.now()` during render. Moving that call into
the page would retain the React purity violation. The new
`src/lib/groupCard.ts` data loader instead awaits `connection()` from
`next/server`, calls the existing `getActiveGroupById`, then reads `Date.now()`
and calculates `daysLeft`. The page passes that number to the card. Neither
React function reads a clock; no lint suppression or caching was added.

This follows the installed Next 16.2.10 guide at
`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/connection.md`:
request-dependent output and synchronous database drivers such as
`better-sqlite3` should await `connection()` before querying. Every loader call
crosses that boundary and performs a fresh lookup and clock read. Existing
`getActiveGroupById` behavior is unchanged, including deletion only when
`expiresAt < now` and returning null for missing/expired groups. The page still
calls `notFound()` for those results. That existing expiry check and the card
calculation each sample the clock after the lookup.

The formula remains `Math.max(0, Math.ceil((expiresAt.getTime() - now) /
(24 * 60 * 60 * 1000)))`: fixed 24-hour periods, ceiling, then a zero clamp.
One millisecond remaining displays 1; exactly one day displays 1; one day plus
one millisecond displays 2; expiry and negative values calculate 0. The exact
JSX wording `D-{daysLeft} 후 자동 삭제`, all card layout/classes, and the separate
expiry-date banner are preserved. This is a request snapshot, with no live
countdown added. A group can expire while the remainder of a request loads,
as with the existing lookup policy; subsequent requests check expiry again.

The build script is now `prisma generate && next build`. Generation therefore
runs before Next resolves `@/generated/prisma/client`, and a generation failure
stops the build. Existing schema output and gitignore already target
`src/generated/prisma`; no generated client is included. Dependencies, lockfile,
schema/migrations, and Next version are unchanged.
